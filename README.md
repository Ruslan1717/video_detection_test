# Детектор людей в толпе с использованием YOLOv8 и простым трекингом на Python.

## Описание проекта

Этот проект предоставляет решение для обнаружения и отслеживания людей в видеопотоке с использованием модели YOLOv8 и простого алгоритма трекинга. Система способна:

- Обнаруживать людей в реальном времени
- Отслеживать перемещение людей между кадрами
- Считать общее количество людей
- Визуализировать результаты с bounding boxes и треками
- Генерировать детальную статистику

## Особенности

- **Модель YOLOv8**: Использует современную архитектуру для высокой точности детекции
- **Простой трекинг**: Алгоритм на основе расстояния между центрами bounding boxes
- **Визуализация**: Цветные bounding boxes и треки для каждого человека
- **Статистика**: Подробная информация о количестве людей, FPS и прогрессе обработки
- **Гибкость**: Поддержка разных размеров модели YOLOv8

## Основные метрики

- Модель: YOLOv8-M (medium)
- Общее время обработки: 785.37 секунд (≈13 минут)
- Количество кадров: 705
- Средний FPS: 0.90
- Всего детекций: 10823
- Среднее количество людей на кадр: 15.35
- Диапазон обнаружения: 16-18 человек в кадре

### Анализ эффективности

## Положительные аспекты:

- Стабильность детекции - небольшой разброс между минимумом и максимумом (16-18) указывает на consistent работу
- Высокое количество детекций - в среднем 15.35 человек на кадр показывает хорошее покрытие
- Работоспособность трекера - система в целом справляется с отслеживанием объектов

## Проблемные области:

1. Проблема с детекцией мелких объектов - часть людей в толпе не распознается
   Причина: Мелкие объекты теряются при downscale входного изображения, низкое разрешение для distant people
   Влияние: Неполный охват всех людей в сцене

2. Проблема с трекингом (ID switching) - одному и тому же человеку присваивается новый ID
   Причина: Простой трекер на основе расстояния не справляется с окклюзиями и пересечениями траекторий
   Влияние: Неточная статистика и анализ перемещений

3. Ложные срабатывания - модель принимает картины/объекты за людей
   Причина: Недостаточная специфичность модели к человеческим фигурам в сложных условиях
   Влияние: Завышенный счет людей, неточная аналитика

4. Производительность - низкий FPS (0.90)
   Причина: Тяжелая модель и неоптимизированный пайплайн обработки
   Влияние: Длительное время обработки, невозможность real-time применения

### План улучшений

## Этап 1: Улучшение детекции мелких объектов

Методы решения:

- Увеличение входного разрешения - обработка видео в более высоком разрешении (1280px вместо 640px) для сохранения деталей мелких объектов
- Много-масштабная детекция - запуск детекции на нескольких масштабах изображения с последующим объединением результатов
- Специализированные архитектуры - использование моделей, оптимизированных для детекции мелких объектов:
- Добавление P2 слоя в YOLO для детекции очень мелких объектов
- Использование Feature Pyramid Networks (FPN) для лучшего представления объектов разного размера

Адаптация параметров детекции:

- Снижение порога IoU для лучшего перекрытия объектов
- Настройка confidence threshold для баланса между precision и recall

## Этап 2: Улучшение трекинга

Методы решения:

- Внедрение продвинутых алгоритмов трекинга:
- DeepSORT - комбинация deep learning и фильтра Калмана
- ByteTrack - использование как высоко-, так и низкодостоверных детекций
- OC-SORT - оптимизирован для сцен с окклюзиями

Добавление визуальных признаков:

- Использование ReID (re-identification) моделей для извлечения appearance features
- Сравнение визуальных характеристик при повторных появлениях объектов

Улучшение ассоциации треков:

- Комбинация расстояний по позиции, размеру и визуальным признакам
- Учет динамики движения и предсказание позиций

## Этап 3: Уменьшение ложных срабатываний

Методы решения:

- Пост-обработка детекций:
  - Фильтрация по соотношению сторон bounding box (исключение слишком узких/широких боксов)
  - Проверка минимального размера детекций

Дообучение модели:

- Fine-tuning на данных, специфичных для целевой среды
- Добавление hard negative examples (картины, statues, etc.)

Ансамблирование моделей:

- Комбинация детекций от разных моделей
- Использование temporal consistency - проверка устойчивости детекций во времени

## Этап 4: Оптимизация производительности

Методы решения:
Выбор модели:

- Тестирование разных размеров YOLOv8 (nano, small) с оценкой trade-off точность/скорость
- Рассмотрение специализированных моделей для edge devices

Оптимизация пайплайна:

- Использование асинхронной обработки
- Оптимизация операций с помощью TensorRT или OpenVINO
- Кэширование результатов для статичных сцен

Аппаратные улучшения:

- Использование GPU с большим количеством ядер
- Оптимизация памяти и batch processing
